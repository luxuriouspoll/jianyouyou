面向**任意目标岗位**（运维、开发、测试、数据、产品、云原生等）的简历优化方法论，以 `SKILL.md` 形式开源，可直接接入 AI 编程助手或简历优化 Agent。


## 这是什么？

一套**只改表达、不编事实**的简历优化方法论。目标是在「事实不变」的前提下，让简历：

- **结构更清晰**：基本信息 / 教育 / 技能 / 项目 / 成果，版块规范、重点突出；
- **表达更专业**：把「负责 XX」改写为「主导完成 XX，达成 XX」；
- **成果更量化**：规模、效能、成本、稳定性用真实数字说话；
- **岗位更匹配**：按目标岗位（运维 / 开发 / 测试 / 数据 / 产品…）对齐关键词、突出相关能力；
- **可评分**：五个维度（内容完整度 / 岗位匹配 / 排版结构 / 专业表达 / 成果量化）按 0-100 评分并给出档位。

它不是「一键生成一份假简历」，而是把用户**已确认真实**的经历，用更专业的方式讲出来。


## 为什么开源？

把简历优化里最难、也最容易被 AI 做错的两件事——**「真实性边界」**和**「从琐碎到有成果的改写」**——沉淀成可复用、可校验的方法论：

1. **可复用**：一次打磨，多岗位通用，运维 / 开发 / 测试 / 数据 / 产品都能用；
2. **可审计**：每条原则都明确「能做什么、绝不能做什么」，方便接入任意 Agent 时做质量回归；
3. **可迭代**：社区可以补充岗位细则、量化模板、评分锚点，一起把「写得专业又不编造」这件事做好。

## 核心原则（最高优先）

### 真实性（不可违背）

- 只改写、重组、强化用户**已确认**的真实经历；
- 严禁新增或篡改姓名、公司、项目、职责、技能、证书、日期、量化数字、成果；
- 缺失信息必须提示补充，或标记为「待完善」，绝不自行推断成事实；
- 允许修正明显的拼写 / OCR / 术语错误（只改写法与大小写，不改事实语义）。

### 版本化输出

- 每个版块按「用户原文」逐项呈现 **原始 → 优化后**，并说明改了什么；
- 只做表达与结构优化，不改变事实；
- 输出前自检：技能去重分类、无空话、每条经历有结果或量化、版面基本一页、与岗位关键词自然命中。

## 目录结构

```text
jianyouyou-resume-optimization/
├── SKILL.md                 # skill 入口（name / description / 核心约束）
├── README.md                # 本说明
└── references/
    └── principles.md        # 详细版唯一事实来源（全部版块原则）
```

> `SKILL.md` 仅保留概览与指针，具体细则集中在 `references/principles.md`，单一事实来源，避免两处重复。

## 快速使用

### 方式一：作为 Skill 安装（推荐）

把本目录放到你的 Skill 目录（如 Codex 的 `~/.codex/skills/jianyouyou-resume-optimization`），Agent 即可按 `SKILL.md` 的说明加载 `references/principles.md` 执行。

### 方式二：作为上下文 / Prompt

直接把 `SKILL.md` + `references/principles.md` 的内容抛给任意大模型，按其中原则对已有简历做诊断与改写。

## 评分档位（0-100）

| 分数 | 档位 | 特征 |
| --- | --- | --- |
| 81-100 | 优 | 明确、有量化、与岗位强相关、结构清晰、无空话 |
| 61-80 | 良 | 基本清晰，有部分量化，匹配度中等，偶有空话或冗长 |
| 41-60 | 中 | 结构可辨但较乱，量化偏少，匹配一般，空话较多 |
| 21-40 | 弱 | 版块混杂 / 信息缺失，几乎无量化，多条空话 |
| 0-20 | 不符 | 信息严重不全或与目标岗位明显不符 |

> 打分需与问题清单一致：问题里提到的维度才可给低分；优化前后差值应与实际改动相符，避免凭空暴涨。

## 免责声明

- 本方法论**只基于用户已确认真实的经历**做改写与重组，AI 不编造任何事实与数字；
- 输出结果仅供个人求职参考，最终是否采纳由用户判断；
- 不同模型对原则的遵循程度不同，建议在接入前用真实简历做一次质量回归。
